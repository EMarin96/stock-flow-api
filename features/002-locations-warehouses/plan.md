# 002 · Locations/warehouses — Plan

## Approach

Implement as Vertical Slices under `src/Application/Locations/`, one folder per use case (CreateLocation, UpdateLocation, GetLocationById, GetLocations, DeleteLocation), mirroring the exact shape of `src/Application/Products/`. CQRS: write commands go through EF Core, read queries go through Dapper. Reuses the project's existing shared infrastructure — `Entity`/`AuditableEntity`, `IUnitOfWork`, the custom Mediator, `Result`/`Error` — introduced in feature 001, none of which is Product-specific.

## Implementation

1. `src/Domain/Locations/LocationCode.cs` — Value Object, `sealed record` with `Value` (string). Private constructor; `Create(string value)` guard clauses (empty/whitespace, length > 32) throw `DomainValidationException`, mirroring `Sku.cs`.
2. `src/Domain/Locations/Country.cs` — `enum Country { US, CR }`, a closed set (no external call needed for `Country` itself).
3. `src/Domain/Locations/Address.cs` — Value Object, `sealed record` with `AddressLine1?`, `AddressLine2?`, `AddressLine3?` (string, always independently optional, no cross-validation), `City` (string, required), `State` (string, ISO2 code, e.g. `"CA"`, required), `Country` (`Country`, required). Private constructor; `Create(string? line1, string? line2, string? line3, string state, string city, Country country)` guard clause: simple non-empty checks on `state`/`city` (mirroring `Sku`'s single-value guard clause) — `state`/`city`/`country` are unconditionally required, no "all or none" logic (there's no valid "trio absent" state anymore). Domain has no I/O, so it cannot confirm the `State`/`City` actually exist — that check belongs in the Application layer (see below). Max lengths: `AddressLine1/2/3` 200 each, `City` 100, `State` 10.
4. `src/Domain/Locations/Location.cs : AuditableEntity` — `Code` (`LocationCode`), `Name` (string), `Address` (`Address`, **non-nullable** — every `Location` has an address, since `Country`/`State`/`City` are mandatory; see Decisions). `Create(string code, string name, string? line1, string? line2, string? line3, string state, string city, Country country)` and the equivalent `Update(...)` (code immutable, same convention as `Sku`; `state`/`city`/`country` required, `line1/2/3` optional) — build `LocationCode`/`Address` internally, same primitive-in/VO-inside pattern as `Product`.
5. EF Core `LocationConfiguration` (Infrastructure) — `Code` via `HasConversion(...)`, unique index on `Code`; `Address` as an EF **owned type** (`OwnsOne`), **required** as a whole (falls out of the non-nullable `Address` property; confirm explicitly with `.Navigation(l => l.Address).IsRequired()` if EF's model validation doesn't infer it), with `State`/`City`/`Country` columns `NOT NULL` and `AddressLine1/2/3` nullable; Global Query Filter `!IsDeleted`.
6. **Regenerate the existing `AddLocationsTable` migration** (don't add a second one) — this feature hasn't merged/shipped yet, so it's still pre-merge rework, consistent with how feature 001's Value Objects refactor regenerated `InitialCreate` for the same reason.
7. Dapper read queries (Infrastructure) for `GetLocationById`/`GetLocations`, filtering `IsDeleted = false` explicitly, reusing `ISqlConnectionFactory`.
8. `src/Application/Locations/Shared/` — `ILocationWriteRepository` (`CodeExistsAsync`, `GetByIdAsync`, `AddAsync`), `ILocationReadRepository`, `LocationDto` (flat/primitive — `Code`, `Name`, `AddressLine1/2/3?`, `State`, `City`, `Country` (non-nullable — every `Location` has these) — same convention as `ProductDto`, no VOs on the read side), `LocationMappingExtensions`, `LocationErrors` (`NotFound(id)`, `CodeAlreadyExists(code)`, `ValidationFailed(validationResult)`, `InvalidState(country, state)`, `InvalidCity(country, state, city)`, `ReferenceDataUnavailable()` — same shape as `ProductErrors`, extended for address reference-data validation).
9. `src/Application/Locations/Shared/ICountryReferenceDataService.cs` — new interface: `Task<IReadOnlyList<StateInfo>> GetStatesAsync(Country country, CancellationToken ct)` and `Task<IReadOnlyList<CityInfo>> GetCitiesAsync(Country country, string stateIso2, CancellationToken ct)` (`StateInfo`: `Iso2`/`Name`; `CityInfo`: `Name`). Implemented in Infrastructure against the external [countrystatecity.in](https://docs.countrystatecity.in/) API (verified endpoints: `GET /v1/countries/{iso2}/states`, `GET /v1/countries/{countryIso2}/states/{stateIso2}/cities`, auth header `X-CSCAPI-KEY`).
10. `src/Infrastructure/ExternalServices/CountryStateCity/` — `CountryStateCityOptions` (Options Pattern: `BaseUrl`, `ApiKey` — a real secret, bound from `dotnet user-secrets` locally / a GitHub Actions secret in CI, never a committed `appsettings*.json`); `CountryStateCityApiClient` (typed `HttpClient` via `AddHttpClient<...>()`, no new NuGet package, no retry/circuit-breaker library — a single call with a sane timeout is enough for this scope); `CachedCountryReferenceDataService` (decorates the client with `IMemoryCache` — states cached per `Country` with no expiration, cities cached per `(Country, State)` with no expiration, populated lazily on first request for that pair; registered as `ICountryReferenceDataService` in DI). `Program.cs` gets a small startup hook that eagerly warms the states cache for both `US` and `CR` (via an `IHostedService`) so the first real request never pays that latency — if the warm-up fails (external API down at startup), it logs a warning rather than blocking app startup, and the first real request that needs it retries the fetch on demand.
11. `tests/StockFlow.Tests/TestDoubles/InMemoryCountryReferenceDataService.cs` — a fixed, hardcoded fake (e.g. `US`→`CA`→`"Los Angeles"`, `CR`→`SJ`→`"San José"`) implementing `ICountryReferenceDataService`, registered in `LocationApiFactory` via `ConfigureTestServices`. Tests never call the real external API — no API key needed in CI, no network flakiness, no rate limits.
12. `src/Application/Locations/CreateLocation/` — Command (`Code`, `Name`, `AddressLine1/2/3?`, `State`, `City`, `Country`) + Handler (pre-checks `Code` uniqueness before insert, in addition to the DB unique index; always calls `ICountryReferenceDataService.GetStatesAsync`/`GetCitiesAsync` to confirm `State`/`City` are real — case-insensitive match — surfacing `LocationErrors.InvalidState`/`InvalidCity`/`ReferenceDataUnavailable` as appropriate, never a raw exception) + Validator (`Code`/`Name`/`State`/`City` required via plain `NotEmpty()`, `Country` via `IsInEnum()` — no conditional "all or none" rule anymore; address lines independently optional).
13. `src/Application/Locations/UpdateLocation/` — Command + Handler (404 if not found/soft-deleted); `Code` is not part of the update command (immutable). Same required-field + reference-data validation as Create.
14. `src/Application/Locations/DeleteLocation/` — Command + Handler; soft delete (`IsDeleted = true`, `DeletedAt = now`); 404 if not found/already deleted.
15. `src/Application/Locations/GetLocationById/` — Query + Handler (Dapper); 404 if not found.
16. `src/Application/Locations/GetLocations/` — Query (`page`, `pageSize`) + Handler (Dapper, offset-based pagination) + Validator, same bounds as `GetProductsValidator`.
17. `src/Api/Endpoints/LocationEndpoints.cs` — Minimal API endpoints (create/update/get-by-id/list/delete), wired to the Mediator, mapped in `Program.cs`; Swagger annotations/response types per endpoint. `Program.cs` also registers `AddHttpClient<...>` for `CountryStateCityApiClient`, `AddMemoryCache()`, the states-warmup hosted service, and binds `CountryStateCityOptions`.
18. Tests: unit tests per handler/validator + `LocationCodeTests`/`AddressTests` for the new VOs' guard clauses (confirming `State`/`City`/`Country` are unconditionally required and address lines are independently optional — no more partial-trio/all-or-none cases, since there's no valid "trio absent" state), plus Handler tests for invalid state/invalid city/reference-data-unavailable using `InMemoryCountryReferenceDataService`. Integration tests for the 5 endpoints in `tests/StockFlow.Tests/Api/Locations/LocationEndpointsTests.cs`, reusing the existing shared `PostgresContainerFixture`/`"Postgres collection"` with a `LocationApiFactory`/`LocationApiFactoryFixture` pair mirroring the `Products` ones (registering `InMemoryCountryReferenceDataService` via `ConfigureTestServices`), truncating the `Locations` table between tests. Test method names follow the established `MethodUnderTest_Scenario_Expected` convention.

## Decisions

- **`LocationCode` and `Address` as Value Objects** — same rationale as `Sku`/`Money` in feature 001: guard clauses throwing `DomainValidationException` (not `Result<T>`, to keep `Domain` free of an `Application` dependency), conversion from primitives happens only inside `Location`.
- **`Address` is mandatory on `Location`; `Country`/`State`/`City` are unconditionally required, `AddressLine1/2/3` are always independently optional** — a `Location` cannot exist without a country, state, and city (this reverses the original feature 002 spec's "address is optional" behavior — a deliberate, confirmed change). This was chosen specifically to resolve an EF Core warning ("optional dependent using table sharing without any required non shared column") that appeared because every column of the `Address` owned type was nullable, making it structurally ambiguous whether a row's owned entity was "absent" or "present with everything empty." Making `Address` itself required removes the ambiguity by construction — no need to split `AddressLine1/2/3` out of the VO or add an artificial sentinel column. `AddressLine1/2/3` stay independently optional with no cross-field rule at all — there's no more "all or none" logic anywhere, since the trio is simply always required now, full stop.
- **`Country` is a closed Domain enum (`US`, `CR`)** — no external call needed; the business only supports these two countries today.
- **`State`/`City` are validated against real reference data from the external [countrystatecity.in](https://docs.countrystatecity.in/) API**, not accepted as arbitrary text — via `ICountryReferenceDataService`, defined in Application and implemented in Infrastructure against the verified endpoints (`/v1/countries/{iso2}/states`, `/v1/countries/{countryIso2}/states/{stateIso2}/cities`, header `X-CSCAPI-KEY`).
- **States cached eagerly (US+CR, ~57 rows total, at startup), cities cached lazily (per `Country`+`State`, on first real use, kept indefinitely)** — researched and deliberately sized this way: the API's full city dataset is large enough (tens of thousands of rows across all US states) that eagerly caching everything would be wildly disproportionate for an app that will have a handful of `Location` rows. Country/state/city data essentially never changes, so once cached, entries are kept for the app's lifetime rather than expired.
- **If the reference-data service can't be reached and nothing is cached yet for what's needed, the write is rejected** (`LocationErrors.ReferenceDataUnavailable`) rather than silently accepting unvalidated `State`/`City` values. The states-cache startup warm-up itself does not block app startup on failure — it logs a warning and lets the first real request retry.
- **`City` is always identified/stored by name, never by the external API's numeric `id`** — considered and rejected using `CityId` instead of/alongside the name, permanently, not just for this iteration. Rejected because (a) no client can supply a valid `CityId` without a not-yet-built proxy feature already existing (a client can only ever type/select a city *name* today), and (b) a third-party integer ID stored in our own database would be opaque without cross-referencing that external provider, whereas a name is self-describing directly in our data.
- **Exposing the reference data as StockFlow's own proxy endpoints (`/api/countries`, `.../states`, `.../cities`) is a separate future backlog feature**, not part of this one — it would let a frontend get dropdown options through this API instead of calling the external provider directly, built on top of the same `ICountryReferenceDataService`/cache introduced here.
- **Tests use a hardcoded in-memory fake (`InMemoryCountryReferenceDataService`), never the real external API** — keeps CI hermetic: no API key needed in the pipeline, no network flakiness, no third-party rate limits, consistent with why Postgres itself is a Testcontainer rather than a shared remote instance.
- **`Code` uniqueness via DB unique index + pre-check** — identical pattern to `Sku`: the unique index is the final safety net against race conditions; `CreateLocationHandler` pre-checks first to return a clean business validation error instead of a raw DB constraint violation, both funneled through the existing `IUnitOfWork`.
- **Regenerated migration, not an additional one** — since this feature hasn't merged/shipped yet, `AddLocationsTable` is regenerated in place rather than stacking a second migration for the Address rework (mirrors how feature 001's Value Objects refactor regenerated `InitialCreate` while it was still unmerged).
- **Shared `LocationErrors`, from the start** — feature 001 initially duplicated error construction and only centralized it retroactively; this feature applies the now-documented `tech-stack.md` convention (shared error factory per feature) from day one, extended here to cover the reference-data validation errors too.
- **No retry/circuit-breaker library (e.g. Polly) added for the external API call** — a new NuGet dependency requires project-owner sign-off per `tech-stack.md`'s hard limits, and a single call with a sane `HttpClient` timeout is enough for this scope; revisit only if real-world flakiness proves it's actually needed.

## Risks

- **Dapper reads forgetting the `IsDeleted = false` filter** — same risk as Product; mitigate the same way (shared SQL fragment/constant, a test asserting soft-deleted locations never appear in list/get-by-id).
- **Race condition on `Code` uniqueness** between the pre-check and the insert — mitigated by the DB unique index, translated by `IUnitOfWork` into the same business `Result` as the pre-check.
- **A `Location` missing `State`/`City`/`Country` silently persisted** if the now-unconditional "required" validation rule is missed on either the Application (`FluentValidation`) or Domain (`Address.Create`) side — both layers must enforce it, not just one (defense in depth, same pattern as every other required field in the project).
- **City name matching is fragile** — the API's Basic tier returns cities by name only (no stable code), so matching is case-insensitive exact-string comparison. Accents, alternate spellings ("Saint Louis" vs "St. Louis"), or duplicate city names within a state could cause false rejections. Accepted for now, not solved by this feature; the future proxy-endpoints feature (see Backlog) mitigates it in practice by having clients always select from — and echo back — a value StockFlow itself already returned, rather than typing one freehand.
- **External API outage or rate-limiting** — mitigated by caching (states eagerly, cities on first use, both kept indefinitely), so steady-state traffic rarely calls out at all; a genuinely new `(Country, State)` pair during an outage is rejected with `ReferenceDataUnavailable` rather than silently accepting bad data, per the confirmed decision.
- **`CreatedBy`/`UpdatedBy` staying `null` indefinitely** until the Auth feature (backlog) is implemented — same tracked risk as Product.
